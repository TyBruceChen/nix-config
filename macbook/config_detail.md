# MacBook: standalone Home Manager

This host uses `aarch64-darwin`, username `tianyi.bruce.chen`, home directory
`/Users/tianyi.bruce.chen`, and the repository's existing locked inputs. Its state
version is `25.05`, matching the existing hosts. No nix-darwin is involved.

## Package ownership

| Software | Owner on this Mac |
| --- | --- |
| Git, Vim, tmux, GnuPG CLI (`gpg`) | Home Manager / Nix |
| Zsh customization, Oh My Zsh, Powerlevel10k, plugins | Home Manager / Nix |
| `eza`, `bat`, `nh`, `alejandra`, `home-manager` | Home Manager / Nix |
| Login shell `/bin/zsh` | Apple; Home Manager's Zsh package is disabled |
| Signal, Nerd Font, Flutter macOS SDK, CocoaPods | Homebrew / `macbook/Brewfile` |

Configured CLI tools are excluded from the Brewfile so two package managers do
not declare ownership of the same tool. Already installed Brew Git, tmux, and
GnuPG are left installed; Brew dependencies can also retain their own copies.
The interactive shell puts the Home Manager profile first on PATH.

The Brewfile is deliberately not an inventory of the whole machine. Existing
portable tools (`git-annex`, `git-lfs`, Go, nvm, OpenCode, OpenJDK 17, p7zip,
Poppler, Tectonic, TeX Live, Verilator, and the Codex CLI cask) are not migrated
or declared here. Transitive dependencies are omitted. No existing `mas`
management was found, so no Mac App Store entries are introduced.

`hm.gpg` manages GnuPG, its agent, and Nix-provided `pinentry_mac` on Mac.
Linux continues to use GNOME pinentry. The agent caches a passphrase after its
first entry for up to 30 days (`2592000` seconds), with both the inactivity timeout
and maximum lifetime set in `homeManagerModules/gpg.nix`. Agent restarts and
reboots clear the in-memory cache earlier; this is not the GPG key's expiry date.
The SSH cache settings do not affect OpenPGP Git signing, and SSH-agent support
remains disabled. Activate the Home Manager configuration to apply changes.
Docker support is disabled here; manage Docker Desktop, OrbStack, or Colima
separately.

## How the Brewfile was created and how to reproduce it

The `macbook/Brewfile` was manually curated from the installed software inventory,
not generated by copying every installed package. These read-only commands were
used to inspect the installation:

```bash
brew --prefix
brew list --formula
brew list --cask
brew leaves --installed-on-request
brew info --json=v2 --installed
```

The formula metadata identifies packages installed on request; the leaves list
narrows the candidates but can omit explicitly requested packages that are also
dependencies. The ownership policy above then selects CocoaPods and the three
casks. Repeating the inventory later may produce different candidates, so review
them before changing the manifest. Keep Home Manager CLI tools and transitive
dependencies out of the Brewfile.

To reproduce the current selection exactly, run this from the repository root.
It **overwrites only `macbook/Brewfile`**; it does not install software:

```bash
cd ~/nix-config
cat > macbook/Brewfile <<'EOF'
# Homebrew owns macOS applications, fonts, and native development tooling.
# Home Manager owns configured CLI tools. Do not add formulas for:
# zsh, git, vim, tmux, gnupg, eza, bat, powerlevel10k, nh, alejandra.
# Apple supplies /bin/zsh; Home Manager supplies Zsh plugins and configuration.
# Only requested, installed top-level software within this boundary is listed.

brew "cocoapods" # Native Apple-platform development tooling.

cask "flutter" # Installed macOS SDK distribution, paired with CocoaPods.
cask "font-adwaita-mono-nerd-font"
cask "signal"
EOF
```

Review `git diff -- macbook/Brewfile` afterward. Installation commands are documented
below under "Activate or install applications".

## Shell behavior

Apple's `/bin/zsh` stays the login shell. This configuration does not modify
`/etc/shells` or change the account's shell. Home Manager manages `.zshrc`,
`.zshenv`, and plugins, while preserving the existing `.zprofile` (including its
`/opt/homebrew/bin/brew shellenv` initialization). No second Brew initialization
is added. A fresh Mac must arrange Brew's login-profile initialization separately
using its installed prefix (`/opt/homebrew` or `/usr/local`).

After activation, open a new terminal. Inspect precedence with:

```bash
type -a git vim tmux zsh gpg eza bat nh alejandra
```

Configured CLI tools should resolve through the Nix profile; `zsh` should resolve
to `/bin/zsh`. Existing custom `.zshrc` content is backed up by the activation
command below, not imported automatically. Review it for any local Java/nvm or
other settings you still want. `.p10k16.zsh` contains the prompt configuration;
custom startup commands and aliases live in `homeManagerModules/zsh.nix`.
`shelltree` and `core-keeper-id` are Linux-only. `workF` uses
`~/Documents/codes`, and `osF` uses `~/nix-config` on macOS.

The Mac `rebuild-nix` alias runs `home-manager switch --flake
'/Users/tianyi.bruce.chen/nix-config#macbook'`. It derives the home directory and
target from the configuration. Keep the checkout at `~/nix-config`, or adjust
the alias if it moves. Linux retains its existing rebuild script and behavior.

## Build and validate without activation

Nix with flakes enabled is a prerequisite; installing it is a separate manual
step. From the repository root:

```bash
cd ~/nix-config
nix flake show
nix flake check
home-manager build --flake .#macbook
```

While the new files are untracked, Git-backed flakes exclude them. Use the
working-tree path form, without staging or committing anything:

```bash
nix flake show path:.
nix flake check path:.
home-manager build --flake path:.#macbook
```

If `home-manager` is unavailable but Nix is available, use the Home Manager input
from this repository's lock file:

```bash
nix run --inputs-from path:. home-manager -- build --flake path:.#macbook
```

These commands may download/build store paths and create `result`; they do not
activate a generation. `flake check` alone does not fully validate arbitrary
`homeConfigurations`; build the Mac target explicitly. Linux builds require a
matching Linux builder.

## Activate or install applications (state-changing)

Activation installs the generation and links managed dotfiles, backing up
conflicting files with `.hm-backup`. Preserve any older backups first if that
suffix already exists.

```bash
home-manager switch -b hm-backup --flake .#macbook
```

For the current checkout, including untracked files, the exact command is:

```bash
home-manager switch -b hm-backup --flake 'path:/Users/tianyi.bruce.chen/nix-config#macbook'
```

Before `home-manager` is available, the pinned-input equivalent is:

```bash
nix run --inputs-from path:. home-manager -- switch -b hm-backup --flake path:.#macbook
```

Check Brewfile satisfaction without installing applications:

```bash
brew bundle check --file=./macbook/Brewfile
```

Install/update the declared Brew applications (state-changing):

```bash
brew bundle --file=./macbook/Brewfile
```

No cleanup or automatic uninstall is part of this setup.

## Recover a generation

List retained generations (read-only):

```bash
home-manager generations
```

Choose the store path of a known-good generation from that output, then run its
`activate` script (state-changing):

```bash
/nix/store/REPLACE-WITH-OLD-GENERATION-home-manager-generation/activate
```

Open a new terminal afterward. If shell startup is broken, `/bin/zsh -f` starts
without user startup files so you can run the recovery command. Generation
recovery restores managed configuration, not arbitrary data or Brew packages;
pre-Home-Manager dotfiles remain in their `.hm-backup` files for manual recovery.

## Clean macOS System Data

System Data includes caches, development tools, simulator runtimes, and application
support files. It is not the size of the macOS installation itself. Run only the
cleanup steps for software or data you no longer need; these are manual maintenance
commands, not part of Home Manager activation.

### Measure before and after

Check free space, volume sizes, and Data-volume snapshots:

```bash
df -h /
diskutil apfs list
diskutil apfs listSnapshots /System/Volumes/Data
```

Find the largest directories (sizes below are KiB):

```bash
du -x -k -d 1 "$HOME/Library" /Library/Developer /opt/homebrew /nix \
  /System/Volumes/Data/System/Library/AssetsV2 \
  "$HOME/.android" "$HOME/.gradle" "$HOME/.cache" \
  2>/tmp/macbook-storage-errors.log | sort -nr | head -40
```

`-x` avoids traversing mounted simulator images and counting their contents again.
Permission errors mean the totals are incomplete; inspect the error log if needed.
Directory totals do not map exactly to Settings' System Data classification or
APFS physical usage. Do not add parent-directory totals to their children.

On 2026-10-16, cleanup increased free space from 20.1 GB to 42.6 GB. Remaining
large items included iOS runtime assets (17.5 GB), Xcode files mostly consisting
of iOS DeviceSupport (11.4 GB), Homebrew (12.8 GB), user Library caches (8.0 GB),
simulator caches (3.3 GB), simulator devices (3.0 GB), and the Nix volume (5.0 GB).
Android SDK/AVD/Gradle data had been removed. These are historical measurements,
not guaranteed reclaimable space.

### Homebrew: unused dependencies and cached downloads

Preview, then perform cleanup:

```bash
brew autoremove --dry-run
brew cleanup --prune=all --dry-run

brew autoremove
brew cleanup --prune=all
```

This removes unused dependencies, old versions, and eligible cached downloads.
Installed packages still occupy space. To inspect large installed packages:

```bash
du -k -d 1 /opt/homebrew/Cellar /opt/homebrew/share | sort -nr | head -20
brew list --formula
brew list --cask
```

TeX Live and Flutter accounted for about 5.0 GB and 4.2 GB respectively during
the scan. Remove unwanted packages with `brew uninstall FORMULA` or
`brew uninstall --cask CASK`. Flutter is declared in `macbook/Brewfile`; remove
its declaration too if it should stay uninstalled on future bundle installs.

Do not use `brew bundle cleanup --force` with this repository's Brewfile: it is
deliberately partial and does not list every package that should remain installed.

### Nix: unused store paths and old generations

Collect unreferenced store paths while retaining existing generations:

```bash
nix-collect-garbage
```

To reclaim more, inspect retained Home Manager generations and remove old profile
generations before collecting garbage:

```bash
home-manager generations
nix-collect-garbage --delete-older-than 30d
```

Deleted generations are no longer available for rollback. Current generations
and other GC roots retain the packages they need. Root-owned profiles can retain
additional packages; if those also need old-generation cleanup, run:

```bash
sudo nix-collect-garbage --delete-older-than 30d
```

This host uses standalone Home Manager, so run the user command as well as any
root cleanup. Do not manually delete `/nix/store` entries. The whole Nix volume
is not reclaimable while the installed configuration still uses it.

### Android SDK, virtual devices, and Gradle

Quit Android Studio and Android emulators, and stop Gradle builds first. The
following commands remove all SDK components and virtual devices, including
saved emulator data, plus Gradle caches and downloaded distributions:

```bash
rm -rf "$HOME/Library/Android/sdk"
rm -rf "$HOME/.android/avd"
rm -rf "$HOME/.gradle/caches" "$HOME/.gradle/wrapper" "$HOME/.gradle/daemon"
```

Project source files and Gradle configuration such as `~/.gradle/gradle.properties`
remain. Android builds require reinstalling the SDK; subsequent Gradle builds
download their dependencies again. These directories occupied about 13.8 GB
before cleanup.

### iOS simulator runtimes and devices

In **Xcode > Settings > Components** (called **Platforms** in some versions),
select unwanted simulator runtimes and choose **Delete**. Use Xcode to manage
runtime assets rather than deleting files inside `/System/Library/AssetsV2` or
`/System/Volumes/Data/System/Library/AssetsV2` manually.

After removing runtimes, delete devices whose runtimes are unavailable:

```bash
xcrun simctl delete unavailable
```

To remove **all** simulator devices and their saved applications/data instead:

```bash
xcrun simctl shutdown all
xcrun simctl delete all
```

Deleting devices does not uninstall runtimes. In the follow-up scan, the iOS 26.5
runtime was still installed and mounted despite some device/cache cleanup.
Recheck both the runtime assets and device directories after using Xcode:

```bash
du -x -sh /System/Volumes/Data/System/Library/AssetsV2/com_apple_MobileAsset_iOSSimulatorRuntime \
  "$HOME/Library/Developer/CoreSimulator" /Library/Developer/CoreSimulator
```

### Other caches and application data

Inspect individual caches before clearing them through the owning application's
settings. Application Support and Containers include saved data and profiles,
so do not delete those directories wholesale.

```bash
du -k -d 1 "$HOME/Library/Caches" "$HOME/Library/Application Support" \
  "$HOME/Library/Developer/Xcode" | sort -nr | head -30
```

Re-run the disk measurements afterward and allow Storage settings time to
recalculate. Compare free disk space to assess the actual gain.
